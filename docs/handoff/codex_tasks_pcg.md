## Our pipeline in one paragraph
`game/scripts/build_levels.py` writes `public/data/levels/level_NN.json` (terrain, blocks, monsters, chests, loadout) with helpers `blk`, `mon`, `stand`, `tower`, `frame` (pillars standing on a base plus one thin floor). `game/scripts/check-data.mjs` validates against `game/schemas/`. The solver (`window.__mm.solveStep` / `sweep` / `play` via `tools/probe.mjs`, wrapped by `tools/solve_levels.sh`) must win each level in the band from `game/scripts/balance_bands.json` (3 to 5 shots mostly) with 0 one-shot wins; bosses are retuned with it. A fort must **stand still at spawn** (0 blocks move in 300 steps) and **collapse** when hit (the best single shot moves or breaks at least 40% of blocks). Boss levels are 4, 8, 12, 16, 20, 24. Daily Mash is generated in `src/content/levelKinds/dailyLogic.js` from a date seed; `scripts/check-daily.mjs` demands 30 deterministic days.

## Task B: procedural fort generator with a stability check and the solver as gate
1. Add `game/scripts/fort_gen.py`: `generate_fort(seed, base, x_min, x_max, tiers, bays, materials_by_tier, keep_clear=[...])` returning `(blocks, floor_tops)` using only `blk` and `frame`-style frames: bottom-up rows as in thesis Ch. 2 (pillars at bay boundaries, one thin floor per tier, optional offset bays so upper tiers do not sit exactly on lower pillars). **Rules** (same as `docs/handoff/agy_task_x8b_boss_fortresses.md`): no block wider and taller than 14 px except thin floors, small iron caps (at most 36x12) and crystal posts; every pillar rests on a floor, ground or plateau top; heavy materials low; keep an opening wide enough for a given monster width and height (`keep_clear`).
2. Add a pure-Python stability check `check_stable(blocks, ground_fn)`: local (no overlaps, every block supported at both ends or by one pillar whose width covers its centre of mass) and global (for each tier, centre of mass of everything above lies within the span of that tier's pillars). Reject and retry with the next seed up to 50 times.
3. Add `tools/gate_level.mjs` (Node, uses `tools/probe.mjs` the way `tools/solve_levels.sh` does): for a level number it prints JSON `{standStill: {moved, dead}, collapse: {pct}, solver: {shots, won}}` and exits non-zero if moved > 0, dead > 0, collapse < 40, or shots outside the band in `balance_bands.json`.
4. Do **not** change any committed level. Add an opt-in flag to `build_levels.py`: `python scripts/build_levels.py --candidates` writes generated variants of the six boss forts to `game/scripts/generated/level_NN_candidate.json` (git-ignored) instead of the real files; document the commands in `docs/monster_mash/11_physics_pcg_notes.md` (append a section) and run the gate on each candidate by copying it temporarily over the level in a throwaway checkout of the file (restore with `git checkout -- <file>` afterwards). Report a table of seed, stand-still, collapse %, shots for the first 3 passing candidates per boss level.
5. Checks: `npm run check`, `npm run build`, `git status public/data/levels` clean at the end. Commit `Procedural fort generator and gate via codex`.
